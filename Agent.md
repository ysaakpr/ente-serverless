# Agent.md

Entry point for anyone — human or model — picking this repository up.

## What this is

**ente-serverless**: an ente-compatible (museum) backend on serverless AWS. Point the stock ente
Photos app at it via the 7-tap custom-endpoint screen and your encrypted photos live in your own
S3 account, at object-storage prices, instead of behind a subscription. It is a clean-room
implementation of museum's API — shapes pinned against `ente-io/ente` server source with
per-handler citations — and oracle capture-parity is the next gate.

Museum never touches file bytes: clients encrypt locally and PUT/GET straight to presigned S3. So
the backend is a pure JSON control plane — a plain zip Lambda, DynamoDB, presigned S3, SES for
one-time tokens, one cron. The compatibility risk lives in SRP-6a handshake math, diff-feed
tombstone semantics and a fast-moving client, not in media processing.

Not affiliated with ente.

### Where this came from

Split out of a two-project monorepo (`photos`) on 2026-08-17, where it was built alongside a
sibling `immich-serverless` project. **None of that sibling is here.** Where a comment or a README
line mentions immich-serverless, it is a lineage note — it records where a pattern (the
ports/adapters split, the tofu module layout, the capture-beats-guessing discipline) was proven
before being copied here. It is never a reference to code missing from this repo.

## Layout

```
Agent.md            this file

TEST-LEDGER.md      generated by `make ledger` — one row per endpoint, never hand-edited
RUNBOOK-M5.md       the stock-app-on-a-real-device gate, step by step
ORACLE-VERSION      the pinned museum image digest and app version
src/                the server — handlers, domain, ports/adapters, workers, and infra/ (OpenTofu)
test/               unit (memory adapters), integration (LocalStack), infra (tofu guards)
tools/              ledger generator, capture-diff harness (skeleton)
docs/agent-core/    the design record — see the table below
```

The infra living under `src/infra` rather than a top-level `infra/` was a deliberate choice at
project creation; the tofu never imports TS and vice versa.

## Ground rules

These are what keep the implementation honest; repeat them to any model given a task here.

1. **Never invent a response shape.** Source-reading beats a schema, and a capture beats
   source-reading. Where a capture disagrees with a handler, *the capture wins* and the handler
   gets corrected — not the other way round.
2. One endpoint = one handler file = one test file. No file over ~150 lines.
3. No cross-handler imports. Shared logic goes in `domain/`.
4. Dependencies: hono, `@aws-sdk/*`, libsodium-wrappers, zod, vitest. Nothing else without a
   written reason.
5. `make test && make typecheck` green before a task is called done.
6. `TEST-LEDGER.md` is generated by `make ledger`. Never hand-edit it.
7. Divergences from museum live in `DECISIONS.md` with a reason — not in a code comment only.
8. Once fixtures exist, never edit anything under `test/fixtures/` — it is captured evidence.
   Where a value cannot be reproduced (ids, another server's timestamps), assert the FORMAT.
9. An entry in a contract allowlist is a claim that a difference was examined and accepted, with
   a DECISIONS row to prove it — not a way to quieten the diff.

## The docs, and what each is for

`docs/agent-core/` is the record of how the design was arrived at. Read it for the *why*; treat
this repo's own docs (README, DECISIONS, NEXT-TASKS) as authoritative for the *what*.

| Document | What it is |
|---|---|
| `ente-serverless-plan.md` | Architecture rationale and the API census — why the project is shaped this way, and why it is separate from the immich work rather than sharing a codebase. |
| `ente-serverless-build-plan.md` | **The executable plan.** Milestones M0–M7, their gates, and the per-handler source citations the implementation was built from. |
| `brainstorm-session1-cost-validation-20260813.md` | The economic premise, 2026-08-13: does self-hosted object storage actually beat a subscription. Provider-agnostic — it predates the choice of ente. |

**A caution on all of them:** these documents predate the implementation. Where one of them and
the running oracle disagree, **the oracle wins** and the doc is the thing that needs fixing;
`DECISIONS.md` records every such correction that has already been found.
